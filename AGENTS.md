# Repository Guidelines

## Project Structure & Module Organization
This repository contains the RUMI Phase 1 standard output template and upload portal.

- `README.md` documents the required grid, variables, file format, and filename convention.
- `create_ncdf.py` generates example RUMI-compliant NetCDF files at the repository root.
- `RUMI_template_2d.nc` is the reference 2D NetCDF template.
- `portal/index.html`, `portal/assets/app.js`, `portal/assets/styles.css`, and `portal/assets/hk-grid.svg` make up the browser UI.
- `portal/api.cgi` is the CGI JSON API entry point.
- `portal/backend/rumi_protocol.py` holds every submission rule (events, required periods, `Init-*` times, archive and file naming, per-file checks). It is standard-library only and is inlined into the downloadable validator, so the portal and participants judge submissions with identical code. Change rules here, nowhere else.
- `portal/backend/portal_lib.py` contains the I/O around those rules: ncdump reading, archive walking, authentication, upload storage, and SQLite helpers.
- `portal/backend/validate_worker.py` validates archives in a detached process; `api.cgi` starts it and the browser polls `upload_status`.
- `portal/downloads/rumi_validate.py` is generated by `tools/build_validator.py`; never edit it by hand.
- `docs/` holds the authoritative submission specification and the participant instructions.
- `portal/backend/manage.py` contains maintenance commands for admins.
- Runtime data belongs under `portal/data/` and is intentionally ignored by Git.

## Build, Test, and Development Commands
There is no compiled build step. Use the following checks before submitting changes:

```bash
python3 create_ncdf.py
```

Generates a sample NetCDF output under `output/`; use it to verify template changes and required `numpy`/`netCDF4` imports.

```bash
python3 -m py_compile create_ncdf.py portal/api.cgi portal/backend/*.py
```

Checks Python syntax for the generator and portal backend.

```bash
python3 portal/backend/manage.py status
```

Initializes/opens the portal SQLite database and prints user, whitelist, and upload counts.

```bash
python3 -m unittest discover -s tests -v
```

Runs the whole suite, including a `node`-driven harness for the browser upload
logic (skipped when `node` is absent) and a check that the generated
`rumi_validate.py` matches `rumi_protocol.py`.

```bash
python3 tools/build_validator.py
python3 tools/sync_downloads.py
```

Regenerates the downloadable validator after any rule change, and refreshes the
copies of `create_ncdf.py` and `RUMI_template_2d.nc` that the portal serves.
`portal/downloads/` is what participants actually receive; it drifted from the
sources once, so both commands have `--check` modes that the test suite runs.

## Coding Style & Naming Conventions
Use Python 3 with 4-space indentation and clear snake_case names for functions, variables, and CLI subcommands. Keep constants in uppercase, following existing examples such as `CORE_2D_VARS` and `DATA_DIR`. Prefer `pathlib.Path` for paths in portal code. JavaScript in `portal/assets/app.js` uses modern browser APIs, `const`/`let`, async functions, and camelCase names. CSS uses custom properties in `:root` and kebab-case class names.

## Testing Guidelines
Run `python3 -m unittest discover -s tests` for every change; it must stay green. Add new cases beside the existing ones in `tests/`. `tests/fixtures/make_fixture_archive.py` builds realistic v3 submission trees (optionally real NetCDF) and is the intended way to get test data. For Python changes also run `py_compile`. For NetCDF schema changes, run `python3 create_ncdf.py` and inspect the generated file with NetCDF tooling where available. Add future tests under `tests/` with names like `test_portal_validation.py`.

## Commit & Pull Request Guidelines
Recent commits use short, imperative subjects, for example `Add RUMI upload portal` and `Clarify 3D variable submission requirement`. Keep commits focused on one logical change. Pull requests should include a concise summary, affected paths or workflows, validation commands run, and screenshots for visible portal UI changes. Link related issues or protocol decisions when relevant.

## Security & Configuration Tips
Do not commit `portal/data/`, SQLite databases, uploaded submissions, generated whitelist files, or local `data_dir.txt` paths. Keep portal secrets and registration codes out of source control. Validate uploaded NetCDF files through `portal_lib.py` rather than duplicating filename or metadata checks in the UI.
